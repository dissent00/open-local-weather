# Open Local Weather: brief for a discussion of options, 2026-09-30

## What it is

- **open-local-weather (OLW)** publishes a daily forecast for one place
  (this deployment: Kisumu, Kenya). It is built from global weather models
  via Open-Meteo (GFS, ECMWF, ICON, UKMO, best_match), and every forecast
  is scored against reanalysis and the airport's station reports. The
  accuracy record is public.
- **An LLM** (Gemini 3.6 Flash, free tier) makes a blended "call", scored
  like a model, and writes the narrative. All arithmetic is in code; the
  LLM reasons and writes.
- **It runs** on GitHub Actions from an external cron, publishes to GitHub
  Pages, and emails a summary.
- **Ensemble** is a Flutter app sharing the forecast logic (a Dart port);
  its users bring their own key.
- **Constraint: free tiers only**, the operator's principle ("think of the
  OLW user with limited resources"). A user's 20 Gemini requests a day are
  theirs, so the pipeline should spend as few as it can.

## The problem

Publishing an LLM forecast reliably on a free tier.

- **Quota.** Gemini's free tier allows 20 requests per model per day. 503
  refusals count against it. The Interactions (queue) API costs about 2
  units a request.
- **Refusals.** Gemini returns 503 "high demand" often.
  - At 15:01Z it served 1 of 7 scored calls (09-21 to 09-27), and none
    since.
  - At 03:01Z it serves most scored calls (6 of 8), but the write-up,
    asked seconds later, was refused on 3 of the last 4 days.
- **Two calls per forecast.** A scored judgment call (small structured
  output) and a narrative (long output). Each prompt is about 40K
  characters of system prompt plus 80K of data.

## What was tried

1. **Retries:** 4 attempts x 2 calls x 2 runs. On bad days this spent the
   daily quota, and the next run got 429s.
2. **OpenRouter free models as a fallback.** They make the scored call
   (90-160 s) but finished the narrative 1 time in 5. Result: figures
   published without a write-up.
3. **Gemini's background queue.** It read 1 of 6 jobs. Its polls were
   refused (503, then 429 "quota exceeded"), it cost double, and it held
   the page back an hour.

The reader's result: many days show the figures under "Write-up
unavailable".

## Decided today

- **One run a day**, 03:01Z (06:01 local). The evening run is gone.
- **Direct Gemini only for the write-up:**
  - 3 tries per call, at +0, +3 and +10 min;
  - a 2-minute pause between the two calls;
  - a second chance for the write-up an hour later, prose only.
- **Worst case 9 Gemini calls a day, 2 on a clean day.** First live test:
  10-01 03:01Z.
- **Roadmap build work stopped.** A multi-run scoring reframe is parked
  mid-way. A documentation cleanup is planned.

## Evidence worth knowing

- **The LLM's call is not adding forecast skill.** A code blend (the
  models' votes weighted by their record, no LLM) has called rain right
  on 82% of days (39 checks), against the LLM's own call at 72% (32
  checks). The spans differ, so treat it as a pointer. The LLM's real
  contribution is prose.
- **Most of the page is already written by code.** High/low, rain, wind,
  sky words, UV and air quality tiles; the thunder-timing phrase; the
  next-three-days phrase; the observation footnotes.
- **The record knows things about this place:**
  - most models under-forecast gusts, GFS by about 13 km/h, now
    corrected in code;
  - ICON runs overnight lows about 2 C too warm;
  - which model calls rain best;
  - whether Kenya's met service beats the global models.
- **The prompt's size** is a large share of the cost and latency, and the
  likely reason free models fail the narrative.

## Options on the table

1. **Keep the LLM, make success cheaper:**
   - a much shorter narrative or prompt;
   - one combined call instead of two (halves requests; they were split
     for quality);
   - a lighter Gemini model for the write-up;
   - a quieter hour.
2. **LLM optional.** Publish a complete, code-written forecast every day;
   the write-up is a bonus when Gemini answers.
3. **Product = the verification record.** "Which model to trust where you
   live", the local met service against the global models, forkable per
   location, possibly an open dataset.
4. **Other free LLM routes** (other providers' free tiers). Not measured
   here; the long narrative output is the hard part.
5. **Paid model for the write-up.** Estimated under a dollar a year as a
   fallback, but it breaks the free-tiers principle.

## Questions to settle

- Is the product the LLM's prose, or the verified multi-model forecast?
- What is the smallest LLM job that still adds value, and can it run
  reliably on a free tier?
- Who is the user: this deployment's readers, people forking it for their
  own place, or app users?
- Can the verification record stand on its own?
